# Diário de estudo — T-034

## O que foi feito

O commit `8f638a2` trocou o nome do George no arquivo de conteúdo (`apps/web/src/conteudo/pt-BR.ts`) de "George Siqueira" para "George Abreu de Siqueira". O site em React passou a mostrar o nome novo sozinho, mas três testes unitários ficaram vermelhos:

- o teste que confere o `<title>` da aba, porque o `apps/web/index.html` ainda dizia "George Siqueira";
- os testes do Cabeçalho e do Rodapé, porque tinham o nome antigo **escrito à mão** dentro do teste.

A tarefa corrigiu as duas coisas:

1. o `<title>` do `index.html` passou a "George Abreu de Siqueira";
2. os testes do Cabeçalho e do Rodapé deixaram de copiar o texto e passaram a ler `conteudo.pessoa.nome`, o mesmo dado que o componente usa. Na próxima troca de nome, eles não quebram.

O dev seguiu a ordem do TDD: primeiro mudou os testes e confirmou que só o do título continuava falhando (era o único problema real); depois corrigiu o HTML. Revisão e QA aprovaram na primeira rodada.

A lição principal: quando o mesmo dado aparece em vários lugares (copiado no teste, repetido no HTML), cada cópia vira um lugar a mais para esquecer de atualizar.

## Conceitos

- **fonte-unica-de-dados-no-front**: o nome do George mora em um lugar só (`pt-BR.ts`), e tanto o componente quanto o teste leem dali. **Por quê**: se o teste copiasse o texto, ele quebraria a cada troca de nome sem que nada estivesse errado no site, o que é um falso alarme. O teste continua conferindo o que importa (o nome aparece no link e no rodapé), sem amarrar um valor específico.
- **arquivo-de-conteudo-e-i18n**: os textos ficam separados do código (RF-09), em `apps/web/src/conteudo/`, e são acessados pelo ponto único `index.ts` (`conteudo` é o mesmo objeto que `ptBR`). **Por quê**: trocar um texto vira editar um arquivo de dados, não caçar strings pelos componentes.
- **index-html-estatico-do-vite**: o `index.html` é a página de entrada do Vite e é servido como está; o React só "monta" dentro dele. O `<title>` desse arquivo não vem do React, então não acompanha o arquivo de conteúdo sozinho. **Por quê**: foi exatamente isso que ficou para trás no commit `8f638a2`. Como o HTML não consegue importar o `pt-BR.ts`, existe um teste que compara os dois e acusa a diferença.
- **importacao-raw-no-vite**: `import paginaHtml from '../../index.html?raw'` traz o arquivo como texto puro. **Por quê**: o teste do título não renderiza nada, só procura `<title>${conteudo.pessoa.nome}</title>` dentro do texto do HTML. É o jeito de testar um arquivo que fica fora do React.
- **title-como-nome-da-pagina**: o `<title>` é o que aparece na aba, nos favoritos e nos resultados de busca, e é o nome que o leitor de tela anuncia ao abrir a página. **Por quê**: um título desatualizado é um erro visível ao usuário e também de acessibilidade, mesmo que o resto da página esteja certo.
- **consultas-por-papel-na-testing-library**: `screen.getByRole('link', { name: conteudo.pessoa.nome })` procura o link pelo papel e pelo **nome acessível**, do jeito que o leitor de tela enxerga. `getByRole('contentinfo')` acha o `<footer>`. **Por quê**: o teste confere o que a pessoa usuária percebe, não detalhes internos (classes, estrutura). Por isso trocar o texto fixo pelo dado do conteúdo bastou.
- **teste-que-protege-convencao**: o teste "o título da aba é o nome do arquivo de conteúdo" não testa um componente: ele protege uma regra do projeto (HTML e conteúdo precisam bater). **Por quê**: foi ele que pegou o esquecimento do commit anterior.
- **tdd**: o dev mudou os testes antes do código e viu qual continuava vermelho. **Por quê**: isso mostrou que o único defeito de verdade no produto era o `<title>`. Os outros dois testes estavam "errados" só por terem o valor copiado.
- **bug-conhecido-com-it-fails-e-test-fail**: no relatório do QA aparecem "falhas esperadas" (web 1, api 2 e um `test.fail()` no e2e, da T-029). **Por quê**: bugs conhecidos ficam registrados como testes que *devem* falhar. A suíte continua verde e avisa quando o bug for corrigido, porque aí o teste para de falhar.
- **tipos-de-teste-unitario-rota-e2e**: o e2e já passava antes da correção, porque o `texto-ampliado.spec.ts` usa nomes de teste fixos (`NOME_CURTO`, `NOME_LONGO`) para medir layout. **Por quê**: cada camada de teste olha uma coisa. Aqui foram os unitários que pegaram a inconsistência, e o e2e `pagina-inicial.spec.ts` confirmou o título no navegador real.

## Onde aparece no projeto

- `apps/web/index.html`: o `<title>George Abreu de Siqueira</title>`.
- `apps/web/src/conteudo/pt-BR.ts`: `pessoa.nome`, a fonte do nome.
- `apps/web/src/conteudo/index.ts`: o ponto único que exporta `conteudo`.
- `apps/web/src/conteudo/conteudo.test.tsx`: lê o HTML com `?raw` e confere o `<title>` e o `<html lang>`.
- `apps/web/src/componentes/Cabecalho/Cabecalho.test.tsx`: `getByRole('link', { name: conteudo.pessoa.nome })` com `href="#inicio"`.
- `apps/web/src/componentes/Rodape/Rodape.test.tsx`: `getByRole('contentinfo')` e `toHaveTextContent(conteudo.pessoa.nome)`.
- `e2e/testes/texto-ampliado.spec.ts`: usa `NOME_CURTO`/`NOME_LONGO`, independentes do nome real.
- `e2e/testes/pagina-inicial.spec.ts`: confere o título da aba no navegador.

## Exercícios

1. Procure, nos testes de `apps/web/src/componentes/`, outro texto escrito à mão que também existe em `apps/web/src/conteudo/pt-BR.ts` (um título de seção, por exemplo). Troque por uma leitura de `conteudo`, rode `npm test` no `apps/web` e depois mude o texto no `pt-BR.ts` para confirmar que o teste continua verde. Desfaça a mudança no fim.
2. Hipótese: o `<title>` passa a ser definido pelo React (com `document.title = conteudo.pessoa.nome` dentro de um `useEffect`), em vez de ficar fixo no `index.html`. Escreva prós e contras pensando em: o que aparece na aba antes do JavaScript carregar, buscadores e pré-visualização de links, e se o teste com `?raw` ainda faria sentido.
