# Diário de estudo — T-007

## O que foi feito

Até a T-005, o front era uma página provisória: um `<main>` com o nome do George e "Site em construção.". A T-007 montou o **esqueleto visual da página única** em `apps/web`:

- um **cabeçalho** com a marca ("George Siqueira") e o **menu**, que fica preso ao topo enquanto a página rola;
- um `<main>` com as **seis seções**, ainda vazias: Início, Sobre, Stacks, Projetos, Serviços e Contato, cada uma com um `id` (`#inicio`, `#sobre`...) para o menu apontar;
- um **rodapé**;
- o **tema escuro**: todas as cores num único arquivo, `tema.css`, como variáveis de CSS.

No **celular**, o menu vira um botão "Menu" que abre e fecha a lista de links (fecha também ao escolher uma seção ou com Esc). A partir de 48rem (768px), o botão some e os links ficam em linha.

Foi uma tarefa `agente-faz`, feita para servir de **exemplo de referência**: o dev implementou com testes unitários, o code-reviewer aprovou com três opcionais e o qa escreveu os testes e2e de navegação no celular e no desktop. No meio do caminho, a **D1** (decidida pelo orquestrador por delegação do George) aplicou dois opcionais da revisão antes do QA:

1. o `<nav>` do `Menu.tsx` usava `estilos.menu`, uma classe que não existia no CSS Module, então o atributo virava `undefined` (código morto, removido);
2. os comentários diziam "cabeçalho fixo", mas o CSS usa `sticky`, e "fixo" confunde com `position: fixed` (num projeto que também é material de estudo, um comentário errado ensina errado).

O terceiro opcional (a regex de cor fixa do `tema.test.ts` cobre poucos nomes de cor e não olha `style={{...}}` nos `.tsx`) ficou anotado para quando o tema crescer.

## Conceitos

- **fonte-unica-de-dados-no-front**: a lista das seções (`id` + `titulo`) mora só em `secoes.ts`, e tanto o menu quanto a página leem dela. *Por quê aqui:* se o menu e as seções tivessem listas separadas, bastaria esquecer uma para ter um link apontando para uma seção que não existe. Com uma lista só, acrescentar uma seção é mudar uma linha.
- **navegacao-por-ancoras**: cada link do menu é um `<a href="#sobre">` comum, e cada seção tem o `id` correspondente. O navegador cuida da rolagem sozinho. *Por quê aqui:* é uma página única (RF-01); âncora funciona até sem JavaScript, o Tab e o Enter já funcionam (elemento nativo) e abrir `/#servicos` direto também cai na seção certa (o qa testou). `scroll-behavior: smooth` deixa a rolagem suave, mas só para quem não pediu ao sistema para reduzir animações (`prefers-reduced-motion`).
- **cabecalho-sticky-e-scroll-padding**: `position: sticky; top: 0` faz o cabeçalho rolar junto com a página até encostar no topo e ali ficar; diferente de `fixed`, ele continua ocupando o seu espaço e não cobre o começo do conteúdo. O problema: ao seguir uma âncora, o título da seção pararia **embaixo** do cabeçalho. `scroll-padding-top: var(--altura-cabecalho)` no `html` reserva esse espaço. *Por quê aqui:* RF-01 pede o menu acessível ao rolar, e o título de cada seção tem que ficar visível. (O qa achou 1px de diferença, porque o cabeçalho tem 1px de borda além da variável; nada fica coberto, ficou como pendência.)
- **menu-compacto-acessivel**: o botão "Menu" é um `<button>` com `aria-expanded` (diz ao leitor de tela se a lista está aberta) e `aria-controls` (aponta para o `id` da lista, gerado com `useId` do React para ser único). Esc fecha e **devolve o foco ao botão**; escolher um link fecha a lista. Com a lista fechada, `display: none` tira os links da ordem do Tab. *Por quê aqui:* sem esses detalhes, quem usa teclado ou leitor de tela não sabe que existe uma lista escondida, ou fica com o foco "perdido" num link que acabou de sumir (RNF-02).
- **html-semantico-e-regioes-com-nome**: `header`, `nav`, `main`, `section` e `footer` em vez de `div`; um único `<h1>` (o nome do George, na seção Início) e `<h2>` nas demais. O `nav` tem `aria-label="Navegação principal"` e cada `section` usa `aria-labelledby` apontando para o próprio título, então o leitor de tela anuncia "região Sobre". *Por quê aqui:* RNF-02 (acessibilidade); além disso, os testes encontram os elementos **pelo papel** (`getByRole('navigation')`, `getByRole('region', { name: 'Sobre' })`), como uma pessoa usando leitor de tela encontraria.
- **foco-visivel-com-focus-visible**: `:focus-visible { outline: 3px solid var(--cor-foco) }` mostra o contorno quando o foco vem do teclado (Tab), mas não a cada clique do mouse. *Por quê aqui:* quem navega por teclado precisa ver onde está (RNF-02); o qa conferiu contorno de pelo menos 2px e contraste de pelo menos 3:1.
- **tema-com-variaveis-de-css**: as cores são declaradas uma vez em `:root` (`--cor-fundo`, `--cor-texto`, `--cor-destaque`, `--cor-foco`...) e os componentes só usam `var(--cor-texto)`. `color-scheme: dark` avisa o navegador que a página é escura (barras de rolagem e controles nativos também escurecem). *Por quê aqui:* RNF-04; o tema claro da v2 poderá redefinir as mesmas variáveis sem tocar em nenhum componente. O contraste foi pensado para o WCAG AA (pelo menos 4,5:1 para texto normal).
- **teste-que-protege-convencao**: o `tema.test.ts` lê o **texto** de todos os `.css` (`import.meta.glob` com `query: '?raw'`) e falha se achar cor fixa (`#rrggbb`, `rgb(...)`, `white`...) fora de `tema.css`, ignorando comentários. Para isso o `vite.config.ts` libera no Vitest só os imports `?raw` (`css: { include: [/\.css\?raw$/] }`); os imports normais de CSS continuam vazios nos testes. *Por quê aqui:* uma regra como "nenhuma cor fora do tema" é fácil de esquecer; com o teste, o próximo que escrever `color: #fff` num componente vê o `npm test` vermelho com o nome do arquivo culpado. O limite está registrado: a regex não cobre todos os nomes de cor nem `style={{...}}` (D1, item 3).
- **mobile-first-e-media-queries**: as regras "soltas" do CSS valem para o celular; um bloco `@media (min-width: 48rem)` ajusta para telas maiores (esconde o botão, põe a lista em linha). `box-sizing: border-box` e `overflow-wrap: break-word` evitam que algo estoure a largura da tela. *Por quê aqui:* RNF-01 pede nenhuma rolagem horizontal de 360px a 1280px+; o qa conferiu de 360 a 1920px, incluindo 767 e 768px, os dois lados do ponto de troca.
- **vite-react-e-css-modules**: cada componente ganhou sua pasta com `.tsx`, `.module.css` e teste (`componentes/Menu/`, `componentes/Secao/`...). O `App.module.css` da T-005 saiu; os estilos da página provisória foram para `Inicio.module.css`. *Por quê aqui:* as classes de um componente (`.lista`, `.link`) não colidem com as de outro, e tudo que é do componente fica junto.
- **tipos-de-teste-unitario-rota-e2e**: o **dev** testou cada componente com Vitest + Testing Library no jsdom (ex.: `aria-expanded` muda ao clicar, Esc devolve o foco). Mas o jsdom **não aplica CSS**, então não sabe se o botão some no desktop ou se há rolagem horizontal. Isso o **qa** testou com Playwright num navegador de verdade, nos projetos "celular" e "desktop"; testes que só fazem sentido num deles usam `test.skip` com `isMobile` (por isso "49 passaram e 7 pulados de propósito"). *Por quê aqui:* cada camada pega o que a outra não enxerga; rodar a suíte de navegação com `--repeat-each 3` mostrou que os testes não são instáveis.

## Onde aparece no projeto

- `apps/web/src/secoes.ts`: a lista única das seis seções (`SECOES`).
- `apps/web/src/App.tsx`: monta `Cabecalho`, `<main>` com `Inicio` e as demais `Secao`, e `Rodape`.
- `apps/web/src/componentes/Cabecalho/Cabecalho.tsx` e `Cabecalho.module.css`: marca, menu e o `position: sticky`.
- `apps/web/src/componentes/Menu/Menu.tsx` e `Menu.module.css`: botão com `aria-expanded`/`aria-controls`, `useId`, Esc com retorno do foco, lista mobile-first e o `@media (min-width: 48rem)`.
- `apps/web/src/componentes/Secao/Secao.tsx`: `section` com `aria-labelledby` e `h2`.
- `apps/web/src/componentes/Inicio/Inicio.tsx` e `Inicio.module.css`: o único `h1` e o `clamp()` que veio do antigo `App.module.css`.
- `apps/web/src/componentes/Rodape/`: o `footer`.
- `apps/web/src/tema.css`: as variáveis de cor e de medida (`--altura-cabecalho`, `--largura-conteudo`, `--espaco-lateral`).
- `apps/web/src/index.css`: `box-sizing`, `scroll-padding-top`, rolagem suave com `prefers-reduced-motion` e `:focus-visible`.
- `apps/web/src/tema.test.ts`: o teste que barra cor fixa fora do tema.
- `apps/web/vite.config.ts`: `css: { include: [/\.css\?raw$/] }` no bloco `test`.
- `e2e/testes/navegacao.spec.ts`: e2e de menu, teclado e rolagem horizontal no celular e no desktop.
- `e2e/apoio/cores.ts`: funções de contraste usadas pelos specs (fica fora de `e2e/testes/` porque o Playwright só roda `*.spec.ts`).
