# Diário de estudo — T-037

## O que foi feito

A T-035 foi a primeira tarefa a rodar num **git worktree** (uma segunda pasta de trabalho do mesmo repositório, para duas tarefas andarem ao mesmo tempo). Ela deixou quatro achados, e a T-037 (tag `orquestracao`, feita pelo `devops` no modo `agente-faz`) os corrigiu:

1. **Backlog antes do worktree**: a linha nova da tarefa no `backlog.md` tinha sido commitada só dentro do worktree. Enquanto isso a `main` ganhou outra linha no mesmo lugar, e o rebase conflitou. Agora a nota e a linha do backlog entram na `main` (commit e push) **antes** de criar o worktree. Se o checkout principal está ocupado com outra tarefa, cria-se o worktree em `main`, commita-se a tarefa lá, faz-se o push e só depois `git switch -c feat/T-XXX-<slug>`.
2. **Limpeza segura no Windows**: o `git worktree remove` deixou para trás atalhos de pasta (junctions) da `node_modules` apontando para pastas já apagadas. Agora a ordem é: parar servidores, apagar a `node_modules` com `cmd /c rmdir /s /q` (que apaga o atalho sem entrar nele), `git worktree remove`, conferir que a pasta sumiu e **nunca** usar `git -C "$WT"` depois da remoção.
3. **Spec alinhada à ADR**: a spec de orquestração ainda dizia "qa → `e2e/**`", o que contradizia a ADR-0004. Passou a apontar para a ADR-0001 e a ADR-0004.
4. **`lerPorta` sem `export`**: a função de `e2e/playwright.config.ts` era exportada, mas ninguém a importava. Os critérios davam duas saídas (tirar o `export` ou escrever testes para ela), e a escolha foi tirar o `export`.

Revisão e QA aprovaram na primeira rodada. Validador, hooks (465 testes), lint, unitários e e2e na porta 5174 (361 passaram, 21 pulados) ficaram verdes.

## Conceitos

- **git-worktree**: várias pastas de trabalho para um mesmo repositório, cada uma na sua branch. *Por quê*: permite rodar uma segunda tarefa sem trocar a branch do checkout principal, onde está a primeira. Detalhe aprendido aqui: dá para criar o worktree em `main`, commitar nele e depois trocar para uma branch nova com `git switch -c`.
- **conflito-de-rebase-em-linhas-proximas**: o git conflita quando dois lados mudam linhas iguais ou vizinhas do mesmo arquivo. *Por quê*: no backlog as linhas novas ficam todas no fim da tabela, então duas tarefas criadas em paralelo sempre "brigam" pelo mesmo lugar. A solução foi de processo (a linha entra na `main` antes do worktree), e não resolver o conflito na mão a cada vez.
- **junctions-do-windows**: o npm workspaces liga os pacotes `@site-apresentacao/*` dentro de `node_modules` com atalhos de diretório (no Windows, junctions) para `apps/*` e `packages/*`. *Por quê*: ferramentas que "seguem" o atalho ao apagar (o Explorer, o `Remove-Item -Recurse` do PowerShell 5.1) podem apagar o **conteúdo do destino**, ou seja, o código de verdade. O `rmdir /s /q` do cmd apaga só o atalho.
- **descoberta-do-repositorio-git**: o git procura a pasta `.git` subindo pelas pastas, a partir de onde está, até achar uma. *Por quê*: depois de remover o worktree, a pasta dele (se sobrou) não tem mais `.git`, então `git -C <pasta do worktree>` sobe até o checkout principal e age nele, na branch da outra tarefa. Daí a regra "nunca `git -C "$WT"` depois do `worktree remove`".
- **porta-do-e2e-por-worktree**: cada checkout que roda o Playwright ao mesmo tempo usa uma porta própria (`E2E_PORTA_FRONT`: 5173 no principal, 5174-5176 nos worktrees). *Por quê*: com `reuseExistingServer`, o e2e de um worktree reaproveitaria o servidor do outro e testaria o código errado. O `lerPorta` valida a variável e para com erro claro se o valor for inválido.
- **test-skip-condicional-playwright**: `test.skip(condição)` pula um teste conforme o projeto (celular ou desktop). *Por quê*: explica os 21 "pulados" do e2e. Não era falha: os testes valem só para um dos tamanhos de tela.
- **adr-como-fonte-unica**: quando um documento repete uma regra que a ADR já define, ele fica desatualizado assim que a regra muda. *Por quê*: a spec ainda dizia "qa → `e2e/**`" depois da ADR-0004. Apontar para a ADR em vez de copiar a regra evita esse tipo de erro.
